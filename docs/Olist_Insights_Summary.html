What we found

  • 01

    Shipping is expensive relative to price

    The typical order pays ~23% of the item's price again in freight, and 46% of items exceed 25%. A real, quantifiable business pain-point — and a less-common angle than delivery-time prediction.

  • 02

    Freight is about the parcel, not the price

    Freight correlates 0.61 with weight, 0.59 with volumetric weight, 0.39 with distance — but only 0.41 with price. This is what makes a fair-freight prediction model well-motivated.

  • 03

    Category drives the burden

    Electronics, telephony and food/drink carry the highest freight-to-price ratios — cheap-but-bulky goods. Product category is a strong feature for both models.

  • 04

    Know the data-quality traps

    Review text is ~88% empty (use the score), ~3% of orders never delivered (filter for delivery-time work), and geolocation had 262k duplicate rows (collapsed to per-zip).

Two problem statements to pick between

Option A · recommended

Freight economics & pricing

  • Classify: will an order have an unfavorable freight-to-price ratio?
  • Regress: predict a fair freight value from weight, volume & distance.
  • Features already engineered in the base table.

distinctive · medium effort · strong signal

Option B · safe

Delivery & satisfaction

  • Classify: will the order be late, or get a 1-star review?
  • Regress: predict delivery days from order.
  • Well-trodden — easier, but many groups do it.

common · lower effort · lower originality

Decisions for tomorrow

  • Pick the problem.

    Option A is more original; B is the safe fallback. Agree on one before feature work starts.

  • Split by feature domain, not by raw table.

    The value lives in one shared base table — freight work already needs product dimensions and distances. Owning a CSV each would make people block on one another.

  • Lock the toolchain.

    Colab + shared Drive folder (IT5006_Project-Data) + one GitHub repo, so everyone runs the same notebook.
